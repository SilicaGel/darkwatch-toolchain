# update-brochure

The brochure is an **exhaustive internal showcase**: every shipped surface gets a row with
thorough copy and a desktop plus a mobile still. Since #2128 it is generated, not
hand-edited.

| Piece | Where | Rule |
|---|---|---|
| Rows and sections | `site/manifest.mjs` | The single source of truth. Edit this, never `index.html`. |
| Page | `site/index.html` | Generated by `node site/build.mjs`; committed; preflight fails if stale. |
| Captures | `tests/brochure/NN-<section>.spec.ts` | One `test("<slug>")` per row. Run inside the lane. |
| Stills | `site/assets/<slug>-{desktop,mobile}.webp` | Written by the captures. |
| Clips | `site/assets/<slug>.mp4` | Rows with `clip: true` get a `test("<slug> @clip", …)` in `tests/brochure/09-clips.spec.ts`; PR 3 of #2128 adds the recorder and encoder. |
| Drift audit | `node site/audit.mjs` | Section `covers` lists versus `docs/feature-inventory.md` headings. |

## Step 0: Decide skip or act (cheap, always first)

```bash
git diff main...HEAD --stat -- client/
for f in $(git diff main...HEAD --name-only --diff-filter=A -- docs/changelog.d/); do
  echo "=== $f"; awk '/^---$/{if(n<2){n++; next}} /^title:/{sub(/^title:[ \t]*/,""); print "Title: " $0; next} n>=2{print}' "$f"
done | head -40
```

Map what changed to manifest slugs (`grep -n "slug:" site/manifest.mjs`). A row that isn't in
the manifest yet means add it (see Adding a row below), not a stale table; the manifest grows
with PRs 1b and 2 of #2128.

|---|---|
| `DashboardPage*`, `CampaignAboutModal*` | dashboard, about-campaign |
| `CampaignWizard*`, `CampaignSettingsPage*` | campaign-wizard, campaign-settings |
| `wt/WtCharacterSheet*`, `WtSheet*`, `WtGearTab*`, `WtSpellsTab*` | character-sheet, gear-inventory, buy-gear, spellcasting |
| `wt/WtPartyRoster*`, `WtRosterRow*` | party-roster, level-up, luck-tokens |
| `WtCombatPanel*`, `WtCombatBar*` | combat-active, turn-order, bench-monster, clear-the-fallen |
| `components/map/*` | map, map-walls-doors, map-line-of-sight, map-fog-memory, map-placed-lights, map-laser-pointer, map-grid-editor, map-dm-view-toggles, map-hidden-monsters, aoe-* |
| `wt/WtQuestsPanel*`, `WtLootPanel*`, `WtNotesPanel*`, `WtHandouts*`, `WtNpcs*` | quests, party-loot, dm-notes, handouts, npc-* |
| `WtMasthead*`, `WtBand*`, `WtPanel*`, `WtUserMenu*` | war-table, wt-dm-and-player-layouts, phone-play, themes-and-scale |

| `index.css`, `styles/wt-*.css`, `styles/wartable.css` | every row: plan a full re-capture |

Fragment sections steer the verdict: `#### Added` → new row; `#### Changed` → re-capture and
maybe re-word; `#### Removed` → delete row, capture, and stills; `#### Fixed` / `#### Internal`
→ usually skip. Write the plan as a short list and confirm with the user. **If everything is
skip, report that and stop here.**

## Adding a row

1. Append the row to its section's block in `site/manifest.mjs` (never insert in the middle:
   theme parity of the rows after it would flip and their stills would be wrong). Fill `slug`,
   `section`, `label`, `headline`, `copy` (HTML, thorough, player/DM voice), `altDesktop`,
   `altMobile`, `clip: false`, `mobile: false` if the surface has no phone equivalent (a row
   with no phone equivalent renders one wide desktop still and a Desktop only note; see
   `references/framing-guide.md`). `node --test site/manifest.test.mjs` must pass.
2. If the row is a new surface, add the inventory heading to the section's `covers` and run
   `node site/audit.mjs`.
3. Add `test("<slug>", ...)` to `tests/brochure/NN-<section>.spec.ts`, following the pattern in
   `06-war-table.spec.ts`: new context, `useTheme(context, themeFor(slug))`, loop both
   viewports, `still()`. Read `references/framing-guide.md` first.
4. Capture: `npm --prefix tests run brochure:capture -- --grep <slug>` (brings the lane up,
   reseeds, runs the one test). Look at both stills. Iterate until they read well.
5. `node site/build.mjs`, open `site/index.html` via `npx serve site/`, check the row.
6. Commit the manifest, the spec, the stills, and `index.html` together. `/ship` handles the
   commit when it invoked you.

### Clip rows

A row with `clip: true` also needs a `test("<slug> @clip", ...)` in `tests/brochure/09-clips.spec.ts`,
built on `recordClip` from `clip.ts` (own context; call `marks.start()`/`marks.end()` around the
action; restore whatever the action changed, either inside the action right after `marks.end()`
if the teardown is invisible, or on a fresh context after `recordClip` returns if it isn't — see
`references/framing-guide.md`'s Clips section). Re-record one clip with the two-step form:

```bash
npm --prefix tests run brochure:lane -- npm --prefix tests run brochure:clips:run -- --grep "<slug> @clip"
npm --prefix tests run brochure:encode -- <slug> --frames
```

Re-record all eight with `npm --prefix tests run brochure:clips` (reseeds, records every `@clip`
test, then encodes all of them). See `references/lane.md`'s Commands and Debugging.

## Changing a row

Edit copy in the manifest, re-capture with `--grep <slug>`, regenerate. If the seed no longer
supports the framing (a state the fixture does not contain), extend
`server/src/rulesets/shadowdark/seeds/brochure-fixture.ts` and its test; never write to the
database while the lane is up.

## Removing a row

Delete the manifest entry, the test, and the two stills (and the mp4 if any). Regenerate. If
the surface is gone from the inventory too, drop it from `covers`.

## New RPG system

Update the system strip in `site/template.html` and regenerate. Rows are ruleset-agnostic by
slug; a second ruleset gets its own showcase seed and section when it ships.

## Reference files

- `references/framing-guide.md` — how to frame a capture (destination not trigger, crop rules,
  theme per row, drag-only panel placement, native confirm dialogs). Load before writing a test.
- `references/lane.md` — the isolated lane: ports, seed, what the fixture contains, debugging.
  Load before running a capture.

## Tone

Write for players and DMs, not developers. Thorough over teasing: explain what the feature
does, why it is useful, and any detail that matters at the table. Never describe the
implementation.
